# Security scan: apps/web and headers (2026-11-22)

Scope: `apps/web/src`, `apps/web/public/_headers`, `apps/web/vite.config.ts`, `apps/web/index.html`. Method: the `vulnerability-scanner` skill, source-to-sink tracing, plus `npm audit --omit=dev` (0 vulnerabilities).

Result: no exploitable finding. Three low defence-in-depth gaps are accepted below.

## Accepted

1. **Wildcard hosts in CSP `connect-src` and `img-src`** (`*.workers.dev`, `*.supabase.co`). Needed because the API gateway and storage hosts differ per environment. Exploiting it needs script execution first, and `script-src` forbids inline and eval. Revisit when the API moves to the custom api subdomain: then replace `*.workers.dev` with that host.
2. **No `Cross-Origin-Opener-Policy` header.** The app has no `window.open`. Clerk sign-in and the bot check may rely on popups or frames, so a COOP header could break sign-in. Accepted until tested against Clerk.
3. **`style-src 'unsafe-inline'`.** React Aria and Faro set inline styles. CSS injection needs an HTML injection first, and none exists (see below).

## Checked, not a problem

- No `dangerouslySetInnerHTML`, `innerHTML`, `eval`, `document.write` or `postMessage` in `apps/web/src`.
- Search snippets are split into text parts and rendered as React text nodes (`search-highlight.ts`), so note text cannot inject markup.
- Search result links use `bookId` and `id` from the API in a same-origin path, so they cannot leave the origin.
- `coverUrl` goes to `<img src>`; CSP `img-src` limits hosts and `img` cannot run script.
- The bearer token is set per request from Clerk; nothing is stored in `localStorage` or `sessionStorage`.
- Sign-out and "clear device data" delete the offline queue database and all caches.
- The service worker has no runtime caching, so API responses with notes are not cached.
- Telemetry: Faro console capture is off, `beforeSend` scrubs items, route patterns only.
- Headers: CSP `default-src 'none'`, `frame-ancestors 'none'`, `base-uri 'none'`, `object-src 'none'`, HSTS preload, `nosniff`, no-referrer, Permissions-Policy; `headers.test.ts` guards script sources.
- Build-time env values are public keys and URLs only.

## Not covered

Runtime behaviour of the deployed headers on Cloudflare Pages, Clerk configuration, the API and database (other phases).

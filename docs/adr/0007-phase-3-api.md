# ADR 0007: Phase 3 API

- Status: Accepted
- Date: 2026-11-21
- Decider: Vikram Nayyar
- Method: `/grill-me` session, two rounds

## Context

Phase 3 builds the API from `docs/requirements.md` (Implementation order, step 3) on the data layer in ADR 0003. Every client reads and writes through it. The product has no domain yet, the owner is the only user, and the owner wants free AI providers that do not train on API data.

## Decision

### Delivery

| Run | Scope |
| --- | --- |
| Run 2 (Musts) | Contract, auth, books (ISBN lookup, past books), sessions with signed audio uploads, transcription, insights, finish flow and reflections, search, export, usage limits, personal access tokens, gateway Worker |
| Run 3 (Shoulds) | Ask the vault, book summary, quote photo OCR, nudge scheduling |

Each run has its own brief in `docs/briefs/`. Run 3 starts only after the owner has reviewed run 2's PRs.

### Shape

- **One Edge Function, `api`,** with Hono routing every path. Handlers are thin; logic lives in `packages/core`.
- **Contract first:** hand-written OpenAPI 3.1 YAML in `packages/api-contract`, with types generated by `openapi-typescript`. API tests validate every response against the spec.
- **Paths under `/v1`.** Errors use RFC 9457 `application/problem+json` with a stable `code` (for example `tier_limit_reached`) and never include note text.
- **Database access:** `postgres` (postgres.js) through the Supavisor transaction pooler. Each request runs in a transaction that sets the `authenticated` role and the caller's JWT claims, so RLS applies (ADR 0003).

### Gateway

- A Cloudflare Worker on `*.workers.dev` forwards to the `api` function in dev and adds a shared secret header. The API rejects requests without it.
- The Worker, its secret (a Terraform `random_password`, passed to the Worker and to Supabase secrets) and its settings are Terraform resources.
- WAF custom rules and the rate limiting rule wait for the domain (launch readiness).

### Auth

- Clerk session tokens for the PWA.
- **Personal access tokens** for the owner's iOS Shortcut, and later possibly the MCP server: a new `api_tokens` table storing only a hash, with RLS and an RLS test, scoped (`sessions:write`, `books:read`), and created, listed and revoked through the API.

### AI providers

| Job | Provider |
| --- | --- |
| Speech-to-text | Groq Whisper |
| Insights, reflection questions, summaries, answers | Groq open model (the cheapest that passes DeepEval); Claude Haiku only if no Groq model passes |
| Embeddings | Supabase built-in `gte-small` (384 dimensions), reached through an interface in core that the Edge wrapper supplies |

- One key: `DEV_GROQ_API_KEY` (repo secret, passed to Supabase secrets by Terraform).
- The `insights.embedding vector(384)` column and its index arrive in run 2. Embeddings are first used in run 3.

### Voice pipeline

- The client uploads audio with a signed URL, then calls `POST /v1/sessions/{id}/process`, which returns `202`.
- Transcription and extraction run in the background (`EdgeRuntime.waitUntil`), moving `status` through `transcribing`, `extracting`, then `ready` or `failed`. The client polls `GET /v1/sessions/{id}`.
- On the free tier, audio is deleted after a successful transcription and `audio_path` set to null; `plus` keeps it.

### Books and export

- Book lookup uses Open Library only, with manual entry as the fallback.
- `GET /v1/export?format=json` returns one JSON file; `format=markdown` returns one Markdown file with a section per book. No zip, audio or photos.

### Limits

- Plan limits live in `packages/core/src/plans.ts` and are enforced from the `usage` table.
- `DEFAULT_TIER` per environment sets new users' tier; dev uses `plus` so the owner can dogfood. Tests cover both tiers.
- Only the monthly tier caps are enforced. Per-user per-minute limits wait for the WAF rate limit at launch readiness.

### Testing

- Recorded responses for MSW are captured once with `DEV_GROQ_API_KEY`, from invented sample notes only.
- DeepEval runs in CI only on PRs touching `packages/core/prompts/`, with a Groq model as the judge.
- `deploy-dev.yml` runs `supabase functions deploy api` after migrations.

## Consequences

- One function keeps auth and cold starts in one place, but a bad deploy takes down every endpoint.
- Until the domain exists, the dev API has no WAF and no per-minute limit; the secret header stops direct calls to Supabase, and the owner is the only user. Revisit before inviting anyone else.
- `gte-small` ties embeddings to the Supabase Edge Runtime; a move to Lambda needs another provider and a re-embed of every insight.
- Groq's free-tier rate limits may throttle background jobs; a failed job sets `status = failed` with an `error_code` and can be retried.
- Personal access tokens are a long-lived credential; they are hashed, scoped and revocable, and are never logged.
